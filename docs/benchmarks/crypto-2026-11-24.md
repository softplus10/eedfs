# Local crypto and format benchmark — 2026-11-24

Source: `5af6a3f`. This measures CPU/memory work on the development machine,
not Proxmox, a mounted writable filesystem, S3, Redis, network or disk throughput.
[Raw CSV](crypto-2026-11-24.csv) includes median/min/max wall-clock seconds.

## Environment and reproduction

- Intel Core Ultra 7 155H, x86_64, 22 visible logical CPUs; heterogeneous cores,
  no CPU affinity or isolation, no container CPU/memory quota.
- Rootless privileged Podman, `rust:alpine`; Rust 1.100.0, musl.
- Portable release profile: opt-level 3, thin LTO, codegen-units=1;
  no `target-cpu=native` override. Crypto libraries may use runtime CPU dispatch.
- 64 MiB logical input per sample, three samples, median reported; one warm-up
  invocation before each case. Three-worker cases each process 64 MiB per worker,
  and include thread creation/join. They are local workers, not network clients.
- Each optional 10 GiB case uses one measured sample of 1,280 8 MiB encryptions,
  plus an untimed warm-up chunk. Output is discarded; memory is bounded by chunk size.
- 39 tests, strict Clippy, formatting, build and real read-only FUSE mount smoke
  passed. These tests do not establish production filesystem correctness.

```sh
cargo run --release --locked --example crypto_bench -- --ten-gib \
  > crypto-results.csv 2> crypto-metadata.txt
```

## Complete chunk processing

MiB/s, logical plaintext bytes. Seal includes HKDF, OS nonce generation, AEAD
initialization, AAD encoding, allocation, one payload copy and tag construction.
Naming HMAC is measured separately, not included. Open includes HKDF, context and
length validation, ciphertext copy, authenticated decryption and plaintext buffer
zeroization on drop. Compact parsing itself borrows slices.

## Primitive costs and 10 GiB streams

- XChaCha20-Poly1305: raw 8 MiB in-place AEAD **893.3 MiB/s**; complete 10 GiB stream seal **13.44 s**, **761.9 MiB/s**.
- AES-256-GCM-SIV: raw 8 MiB in-place AEAD **1,194.6 MiB/s**; complete 10 GiB stream seal **10.76 s**, **951.6 MiB/s**.
- HMAC-SHA256 name generation, including fixed-width inputs, parameter validation and hex output: **2,095,624 names/s**.
- Argon2id 64 MiB, t=3, p=4: **175.3 ms** per password derivation. This is unlock cost, not per-chunk work.

Raw AEAD encrypts an already allocated buffer with a fresh counter nonce per
iteration and a fresh benchmark key per size. It excludes payload allocation,
HKDF and OS randomness. Ciphertext is truncated to input length before the next
iteration; the next input need not be the original plaintext. Complete object
helpers use fresh random nonces. Round-trip verification is performed before
chunk timings; the 10 GiB case measures encryption only.

## Metadata size

A 10 GiB file represented by one allocation run of 1,280 8 MiB chunks has a
**5,215-byte encoded inode body**, including its frame, ID, generation, per-file
naming key/profile, maximum chunk size, allocation ID, first index and length
vector. This excludes the outer wrapped-key/encryption envelope. Each compact
chunk adds **40 bytes** for XChaCha20-Poly1305 or **28 bytes** for AES-256-GCM-SIV.
The file's inode envelope supplies the shared algorithm; chunks do not repeat it.

The flat reference list is currently limited to 4,096 chunks. This is a deliberate
prototype bound, not an arbitrary-file-size implementation; a larger index needs
future format work.

## Interpretation

The local crypto layer sustains hundreds of MiB/s per worker, so it is not an
obvious barrier to 1 GbE throughput on this machine. It does not prove line rate
at 10 GbE: one worker's full seal path here is below 10 Gb/s, while parallel CPU
capacity is higher. S3 request latency/limits, upload parallelism, memory copying,
FUSE work and conflict retries still determine end-to-end performance.
AES-256-GCM-SIV is faster in this run; this does not establish it as universally
faster across CPUs. Small chunks incur visibly higher fixed per-object costs.
The result supports retaining per-file profiles and compact chunks; it does not
justify adding per-chunk algorithm descriptors.
